# 間取り図の読み取り — 設定と運用

間取り図のPDF・画像を読んで、壁・部屋・開口・階段を起こす機能。

## 何を使っているか

| 役目 | モデル | 1回の費用 |
|---|---|---|
| 図面の読み取り | **OpenAI `gpt-6-astra`** | 約 ¥40 / 図面1枚 |
| 紙面のどこに平面図があるか | Google Vertex AI `gemini-2.5-flash`（東京） | 約 ¥0.2 / 1ページ |

3ページのPDFを1回取り込むと **約 ¥120**。

### なぜ Astra なのか

同じ切り出し画像・同じ指示文・同じ仕様書で測った（1階の図面1枚）。

| | 費用 | 所要 | L字の部屋 | 廻り階段 | 寸法線4辺 |
|---|---|---|---|---|---|
| gemini-2.5-pro | ¥16 | 79秒 | ✗ | ✗ | ✓ |
| gpt-5 | ¥26 | 140秒 | ✗ | ✗ | 右辺✗ |
| **gpt-6-astra** | ¥40 | 73秒 | **✓** | **✓** | **✓** |

L字の部屋と廻り階段は、他の2つでは手順を書き直しても出なかった。Astra は
洋室を長方形2つで表して元図と完全一致させ、廻り階段を直進部分に接して置いた。
思考トークンは gpt-5 の1/10（1,552 対 15,360）で、迷わずに答えている。

**位置探しは Gemini のまま。** 大きな領域を1つ答えるだけで、そこに ¥40 を払う
理由が無い。ただし**安ければどれでもよいわけではない**。実測（正解は縦
0.240〜0.600）:

  gemini-2.5-flash  0.240〜0.600  ほぼ一致       ¥0.2
  gpt-5.4-mini      0.184〜0.308  上端だけを切る  ¥0.1

外した範囲で切り出して送ると、読み取りが「図面が無い」と答えて何も返らない。

## 処理される場所

**位置探しは東京リージョン（`asia-northeast1`）。** 読み取りは OpenAI の
既定のリージョン。

間取り図の表題欄には施主名・敷地住所が入ることが多い。OpenAI は API の
データを既定で学習に使わず、保存は不正利用監視の最大30日のみ。日本国内で
処理する設定（データレジデンシー）も API にあるが、**営業窓口での資格確認と
追加の契約条項が要る**（2026年9月時点。未申請）。

Vertex 側は、グローバルの窓口へ流れても**エラーにならず、黙って国外で処理
される**。動いてしまうので気づけない。そのため

- 窓口の組み立ては `worker/vertex.mjs` の `endpointFor` 1か所だけ
- 東京・大阪以外は組み立て自体を拒む
- 設定が国外なら**送信前に 500 で止める**
- `tools/tests/vertex-region.test.cjs` で固定

`asia-northeast3` はソウル。名前が似ているので取り違えに注意。

## 設定

### 鍵（本番）

    wrangler secret put OPENAI_API_KEY
    wrangler secret put GOOGLE_SERVICE_ACCOUNT_JSON

**鍵を置かないと機能は動かない。** OpenAI の鍵が無ければ Gemini で動くが、
L字の部屋も廻り階段も出ない。

ローカルは `.dev.vars`（gitignore 済み）に同じ名前で書く。

### 使用回数の上限

`/api/ai/*` には認証が無い。URLを知っていれば誰でも呼べ、そのまま請求される。

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `AI_DAILY_IMPORTS_PER_USER` | 2 | 1つの接続元が1日に取り込める回数 |
| `AI_DAILY_IMPORTS_TOTAL` | 10 | 全体が1日に取り込める回数 |

既定で **1日およそ ¥1,200** が上限になる。内部では「点」で数えている
（1回 = 33点。呼び出しによって費用が10倍以上違うため）。

数える相手は接続元のIPアドレス。利用者の口座の仕組みがまだ無いため。
定額サブスクと使用回数制限を入れるときは、ここを口座ごとに替える。

画面には「本日あと N 回 読み取れます」を出す。**全体の上限があるので、自分が
使っていなくても使えないことがある。** 押してから断られるより、押す前に
分かっているほうがよい。

### 支払い

OpenAI は**先払いのクレジット**。残高が $0 になると API が止まる。
自動チャージは OFF にしてある（想定外の使われ方をしたときに止まるほうが安全）。
残高は https://platform.openai.com/settings/organization/billing/overview で見る。

### 切り替え

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `AI_IMPORT_PROVIDER` | （鍵があれば openai） | `vertex` にすると Gemini で読む |
| `OPENAI_MODEL` | `gpt-6-astra` | 読み取りのモデル |
| `AI_LOCATE_PROVIDER` | vertex | 位置探しの提供元 |
| `AI_LOCATE_MODEL` | `gemini-2.5-flash` | 位置探しのモデル |

### 他の選択肢を採らなかった理由

| | 理由 |
|---|---|
| Amazon Bedrock | 新方式のAWSアカウントでは東京リージョンと地域別推論が使えない。解除には取り消せないアカウント変更が要り、支出上限も外れる |
| Vertex AI の Claude | us-east5 / europe-west1 / asia-southeast1(シンガポール) のみ。**東京が無い** |
| Vertex AI の OpenAI | 公開重みの gpt-oss のみ。gpt-5 / gpt-image は無い |
| Google AI Studio の APIキー | `generativelanguage.googleapis.com` は**リージョンを指定できない** |

## 設定

### 1. Google Cloud 側（済み）

- プロジェクト `webcad-planner-ai`（この用途専用。請求と権限を分けるため）
- Vertex AI（Agent Platform API）を有効化
- サービスアカウント `plan-import@webcad-planner-ai.iam.gserviceaccount.com`
- 権限は Agent Platform ユーザー（このプロジェクト内のみ）

### 2. 手元で試すとき

```bash
export VERTEX_KEY_FILE=~/.config/webcad/vertex-key.json
node tools/probe_vertex.cjs <PDFか画像> [--model gemini-2.5-flash] [--out plan.json]
```

読み取れた部屋・使用トークン数・**1回あたりの費用**・検算の結果・
寸法がモジュールに乗っている割合が出る。`--out` で保存したJSONは
アプリの「読込」からそのまま開ける。生の応答も `.raw.txt` に残るので、
形が想定と違ったときに**もう一度お金を払わずに**調べられる。

### 3. 本番（Cloudflare Worker）

```bash
npx wrangler secret put GOOGLE_SERVICE_ACCOUNT_JSON
```

鍵ファイルの中身（JSON全体）をそのまま貼る。**鍵はここにしか置かない。**
ブラウザへは出さない（`tools/tests/vertex-region.test.cjs` が、応答にも
エラーにも鍵が出ないことを見ている）。

任意で変えられる設定:

| 環境変数 | 既定値 | |
|---|---|---|
| `VERTEX_LOCATION` | `asia-northeast1` | 東京・大阪以外は拒否される |
| `VERTEX_PLAN_MODEL` | `gemini-2.5-pro` | 費用を抑えるなら `gemini-2.5-flash` |
| `VERTEX_PROJECT` | 鍵の project_id | |

## 費用（2026-09-17 実測）

gemini-2.5-flash、東京、3ページのPDF（3階建て全体）で **1回 約 ¥9**。
画像1枚なら **約 ¥4〜6**。

**費用の8割以上は「思考」。** 答えのJSONは2,000〜4,800トークンで、思考が
8,000〜19,500トークン。だから

- 出力JSONを詰めても安くならない（試したところ逆に思考が84%増えた）
- **思考に上限を置く**のが効く（`thinkingBudget`、既定8192）
- 上限が無いと費用に上限が無い。実際、検算を促す指示を入れたら思考だけで
  32,765トークンを使い切り、答えが0トークンのまま打ち切られた

読み取り結果には使用トークン数が必ず付き、画面にも1回あたりの費用が出る。

## 精度を左右するもの

**解像度がすべて。** 寸法の文字が読めるかで結果が決まる。

- **PDFはそのまま送る。** ベクターなのでAI側で開いたほうが鮮明。実測で
  4辺の寸法線がすべて検算を通り、寸法の99/99件がモジュール上に乗った
- 画像は長辺2400pxまで送る（1568pxでは 7280 を 7290 と誤読した）
- 切り出し（囲む操作）は**任意**。紙面の一部にしか図面が無い画像でだけ効く

## 設計の勘どころ

**部屋はAIに出させない。** 壁と「図に書かれた室名とその位置」だけを出させ、
囲まれた領域は `assets/js/plan-rooms.js` が計算する。両方出させると食い違い、
同じ図面で部屋が3〜9個に変動した。壁から作れば必ず一致する。

**寸法の読み違いは機械的に直す。** 日本の住宅の寸法は 227.5mm（4分の1間）の
倍数に乗るので、50mm以内なら倍数へ寄せる（実測の誤読: 227.5→275、455→450、
7280→7290）。遠い値は触らない — 本当に半端な寸法のこともある。

## まだ足りていないところ

- 壁の読み取りに、実在しない間仕切りが混じることがある。**壁の精度が
  そのまま部屋の精度になる**構造なので、次に詰めるならここ
- 下の寸法線は読み違えることがある（補正で吸収しているが根治ではない）
- 写真（紙を撮影したもの）ではまだ試していない。PDFとCAD出力の画像のみ
