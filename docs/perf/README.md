# 性能の基準

3D の重さを数字で比べるための記録。描画手法（AA・DoF・Bloom・AO など）を足したり、
最適化したりする前後で同じ測定を流し、下限の端末（iPad Pro 第2・第3世代）で
遅くなっていないことを確かめる。

## 測り方

URL の末尾に `bench=1` を付けて開くと、測定が自動で流れ、終わると結果の表が出る。
普段の画面には何も足されない。

| どこで | どうする |
|---|---|
| iPad（Safari） | `https://cad-planner.srapps.us/?preset=2f&bench=1` を開き、1〜2分待つ。表が出たら「結果をコピー」 |
| Mac | `APP_URL=http://localhost:8791/ node tools/perf/run_bench.mjs <ラベル>`。結果は `docs/perf/<日付>-<ラベル>.json` |

3階建ては `preset=3f`。測定中は画面に触らない（触ると操作中の画質に切り替わり、数字が混ざる）。

## 流れる場面

| 場面 | 何をしているか |
|---|---|
| 外観3D・静止 / 内観3D・静止 | 止まって見ているときの最高画質（AO あり） |
| 外観3D・回転 / 内観3D・回転 | 回している間の画質（解像度を下げ、AO・Bloom を止める既存の仕組みが効いた状態） |
| ウォークスルー・歩行 | 前へ歩きながら向きを変える |

## 表の読み方

| 列 | 意味 |
|---|---|
| 入るまで | その場面を押してから、モデルの読み込みが終わって最初の1コマが出るまで |
| fps | 1秒に何コマ出たか。**タッチ端末はアプリ側で30コマに抑えている**ので、iPad では30が上限 |
| 1コマ | 1コマを描き終えるまでの時間（GPU の仕事が終わるまで待って測る）。上限で頭打ちにならないので、余力はこちらで見る。30fps を保つには 33ms 以下 |
| 遅い方 | 遅い側から5%の1コマ。引っかかりの目安 |
| 三角形 | 1コマで描いた三角形の数（AO などの後処理で同じ物を描き直す分も含む） |

読み取れること:
- 最高画質（静止）は Mac でも1コマ 70〜100ms かかる。止まっているときは1回描くだけなので体感は問題ないが、
  この画質のまま歩くことはできない（写真のようなウォークスルーを目指すなら、ここが最大の壁）
- 外観3Dは三角形が約300万。回しても減らない（遠くの物を間引く仕組みが無い）
- ウォークスルーは 30〜43ms で、iPad の上限 30fps に届くかどうかの境目。iPad では下回る見込み
