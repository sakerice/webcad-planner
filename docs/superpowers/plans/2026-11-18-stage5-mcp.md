# 段5 ChatGPT など外の AI から間取りを直す（MCP） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Worker に MCP の受け口 `/mcp` を足し、外の AI（ChatGPT の開発者モードなど）が、共有ルームのプランを段3の操作で直せるようにする。画面で同じルームを開いている人には、変更がその場で映る。

**Architecture:** Worker の `/mcp` は JSON-RPC を読み、道具の呼び出しを対象のルーム（Durable Object `CollaborationRoom`）へ渡すだけにする。操作を当てるのはルームの中。ルームは今のプラン（R2 の元と、積んだ差分）を組み立て、`applyOperations` で1操作を当て、変わった物だけを今までの共同編集と同じ「差分」として積んで全員へ流す。Worker には画面が無いので、操作に要る表（種類ごとの寸法・色・種類の判定）は、画面のコードから機械的に取り出した JSON を使う。

**Tech Stack:** 素の JavaScript（UMD と ESM、ビルド無し）、Cloudflare Workers と Durable Objects（無料プラン）、MCP（Streamable HTTP、JSON で返す。SDK を使わず手で書く）、既存のテストの仕組み。

**Spec:** `docs/superpowers/specs/2026-11-10-one-source-platform-design.md`（3.4、3.6 の段3・段4の結果）

## Global Constraints

- **既存利用者の保存プランと、既存の共同編集が、今の本番と同じに動くこと。** 正解の JSON（`fixtures/compat`・`fixtures/factories`・`fixtures/operations` の `golden.json`）は書き換えない。今ある経路（`/api/rooms` の作成・取得・`/update`・`/save`・WebSocket、`/api/ai/*`）の動きは変えない。
- **Worker で当てた操作の結果は、画面のチャット（`planChatCtx`）で同じ操作を当てた結果と同じであること。** 同じにできない場合（画面の 3D の計算が要る、など）は、近い値で置かずに、その操作を断って理由を返す。照らし合わせは Task 2 の画面テストが行う。
- Worker は無料プランで動く（1リクエストの計算時間 10ms）。重い処理をリクエストごとにしない。表や道具の定義は、モジュールの読み込み時に1回だけ作る。
- 新しい Durable Object のクラスを足さない。`wrangler.toml` の `migrations` を変えない。本番の設定（秘密・変数）を変えない。デプロイしない。
- 認証は付けない。ルームの id（22 文字）を知っていることが権限。`/mcp` から触れるのは、id を渡されたルームと、新しく作るルームだけ。

- 利用者に見える文言に、開発の都合（トークン・座標・id・モデル名）を出さない。日本語で、今の共有のダイアログの調子に合わせる。

## Review Focus

1. `/mcp` 経由で、渡されていないルームや、ルーム以外の物（R2 のほかのキー、AI の回数の記録）に触れないこと。ルームの id の形が違う・無いルーム・期限切れは、例外でなく道具の失敗として返ること（Task 3・4）。
2. 道具の失敗（知らない種類、無い id、ロックした物）のとき、ルームのプランが1項目も変わらず、差分も積まれず、誰にも配信されないこと（Task 3）。
3. 外の AI が直した内容が、画面で同じルームを開いている人にその場で映り、あとからルームを開いた人にも同じ中身で開くこと。今の共同編集の送受信（`shared-relay`）を壊さないこと（Task 3・6）。
4. ルームを大量に作られないこと（作成の回数制限）。数えられないときは作らずに断ること（Task 4）。
5. MCP のクライアントが、古い版の話し方（`initialize` から始める）でも新しい版の話し方（`initialize` なし）でも、道具の一覧を取れて呼べること。知らないメソッド・壊れた JSON・巨大な本文で例外が外へ出ないこと（Task 4）。

### Task 4: `/mcp` の受け口

**Files:**
- Create: `worker/mcp.mjs`、`tools/tests/worker-mcp.test.cjs`
- Modify: `worker/router.mjs`、`worker/ai-quota.mjs`（ルームの作成の数を数える操作。新しいクラスは足さない）

**Interfaces:**
- Consumes: Task 3 の経路と `createRoomWithPlan`、`PlanCoreOperationsCatalog.toMcpTools`。
- Produces: `POST /mcp`（MCP の Streamable HTTP。返事は `application/json` 1つ）。

- 決めごと:
  - **実装の前に、MCP の公式の仕様（modelcontextprotocol.io の specification の最新版と、その前の版）と、OpenAI の Apps SDK / 開発者モードの文書を開いて確かめる。** こちらの調べでは、最新版（2026-07-28）は `initialize` とセッションが無い話し方に変わり、古い版（2025-11-25 以前）は `initialize` から始める。両方に答える。調べた結果と食い違う点は、文書のほうに合わせ、報告に書く。
  - 状態を持たない。`Mcp-Session-Id` は出さない。`GET`・`DELETE` は 405。通知は 202 で本文なし。JSON-RPC の配列（バッチ）は受けない。本文は 64KB まで。`Origin` が付いていて、許す一覧（自分のオリジン、`https://chatgpt.com`、`https://chat.openai.com`、`https://claude.ai`）に無ければ 403。付いていなければ通す。
  - 道具: 段3の操作 10 個（`toMcpTools` の定義に、対象のルームを指す必須の引数 `plan` を足す。値はルームの URL か id）と、`create_plan`（引数なし。空のプランでルームを作り、URL と id を返す）、`open_plan`（`plan`。要約を返す）、`get_plan`（同じ。`open_plan` は設計書にある名前なので残し、中身は同じ）、`inspect_plan`（`plan`）。
  - 道具の注記: 読むだけの道具（`open_plan`・`get_plan`・`inspect_plan`）は `readOnlyHint:true`。ほかは `readOnlyHint:false`、消す操作（`deleteObjects`・`removeWall`）だけ `destructiveHint:true`、ほかは `false`。全部 `openWorldHint:false`。
  - 道具の結果は文字で返す。直す道具は「何が変わったか（件数と警告）」と「house-planner で開く: <ルームの URL>」。失敗は `isError:true` と、直し方の分かる文。知らない道具は JSON-RPC の誤り。
  - サーバの説明（`instructions`）は、最初の 500 字で使い方が分かるように書く: まず `create_plan` か `open_plan`、座標の約束、直したら URL を利用者に伝える。
  - ルームの作成の回数制限: 接続元（`cf-connecting-ip`）ごとに1日 20、全体で1日 300。数える先は、既存の `AiQuota` のクラスを別の名前（`idFromName("room-create")`）で使う。数えられないときは作らずに断る。既存の画面からの `POST /api/rooms` には掛けない（今の動きを変えない）。
  - 空のプランは、画面の「白紙から始める」（`assets/js/plan-data.js` の `chooseBlankPlan`）が作る物と同じ欄にする。
