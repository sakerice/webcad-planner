# 段4 チャットで間取りを直す Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 画面のチャット欄に言葉で頼むと、AI（Claude）が間取りの操作を呼んでプランを直す。1回の依頼は1回の取り消しで丸ごと戻る。

**Architecture:** 往復を回すのはブラウザ。ブラウザは `POST /api/ai/chat` に会話を送り、Worker は回数を数えて Claude に道具（段3の操作の定義）を付けて1回だけ呼び、返事（SSE）を読み解かずにそのまま流す。ブラウザが返事を組み立て、道具の呼び出しを段3の `applyOperations` で**プランの写し**に当て、結果を足してもう一度呼ぶ。Claude が道具を呼ばずに終えたら、写しを本物のプランに入れる。

**Tech Stack:** 素の JavaScript（UMD、ビルド無し）、Cloudflare Workers（`worker/*.mjs`、Durable Object `AiQuota`）、Claude Messages API（SDK を使わず `fetch`。既存の `worker/anthropic.mjs` と同じ）、既存のテストの仕組み。

**Spec:** `docs/superpowers/specs/2026-11-10-one-source-platform-design.md`（3.3、3.5 の回数の節、3.6 の「段3の結果」「段4で決めること」）

## Review Focus

1. 回数を数えられないとき（`AI_QUOTA` が無い・返らない・例外）、チャットは AI を呼ばずに断ること（今の読み取りは通してしまう。チャットでは止める）。札の使い回しで、回数を使わずに何度も呼べないこと（Task 1）。
2. 依頼の途中で失敗・中断・断り（`refusal`）・出力の打ち切り（`max_tokens`）が起きたとき、本物のプランが1項目も変わらず、取り消しの履歴も増えないこと（Task 2・3）。
3. 依頼の途中で本物のプランが変わったとき（共同編集の相手の変更など）、写しで上書きして相手の変更を消さないこと（Task 3）。
4. 1回の依頼で入った変更が、取り消し1回で全部戻り、共同編集の相手にも届くこと（Task 3）。
5. AI の返事の SSE が途中で切れた・壊れた JSON が来た・知らない種類のブロックや出来事が来たとき、例外で画面が止まらず、利用者に分かる文言を出して依頼を終えること（Task 2）。

## 画面とサーバの間の約束（Task 1 が作り、Task 2・3 が使う）

2026-11-17 に実装の最終の形へ合わせた（本文 160KB、札ごとの合計 1MB、往復は最初を含む 8 回、失敗の返事の札、続きの検査、失敗の返事の `code` の欄）。細かい形と実例は `.superpowers/sdd/2026-11-17-stage4-chat/task-1-report.md`。

`POST /api/ai/chat`、本文は JSON `{ ticket?: string, messages: [...] }`。本文は 160KB まで。

- `messages` は Claude の Messages API の `messages` そのまま（`role` は `user` / `assistant`、`content` は文字列かブロックの配列、最初と最後は `user`）。システムプロンプトと道具の定義は Worker が付ける。画面からは受け取らない。
- 送れるブロック:
  - `user` の `content` は、文字列か、`text` と `tool_result` のブロックだけの配列。`tool_result` の `content` は、文字列か `text` のブロックだけの配列。画像・PDF・`search_result` などは送れない
  - `assistant` の `content` は、受け取ったブロックをそのまま返す（知らない種類も通す）。ただし、どの深さにも `source` の鍵があってはいけない
  - `messages` のどこにも `cache_control` を置かない（キャッシュの印は Worker だけが付ける）
  - 入れ子は 12 段まで（`messages` の配列を1段めと数える）
- `ticket` が無い呼び出しは「依頼の最初」。Worker は回数を1回ぶん使い、札を作る。`ticket` がある呼び出しは「同じ依頼の続き」で、回数を使わない。
- 札は会話に結び付く。続きの呼び出しは、**直前の返事で受け取った札**を付け、**前回送った `messages` に足しただけ**の `messages` を送る（前の要素を書き換えない・並べ替えない・鍵の順を変えない。件数は前回より多い）。違えば `ticket_invalid`。前回とまったく同じ `messages`（同じ件数・同じ中身）のやり直しは通る（往復には数える）。札は呼び出しのたびに変わるので、古い札は使えない。
- 往復は、1つの依頼で最初の呼び出しを含めて 8 回まで。札ごとに、Worker が Claude へ送った本文（システムプロンプトと道具を含む）の合計は 1MB まで。どちらを超えても `rounds_exceeded`。
- 成功: `200`、`content-type: text/event-stream`、本文は Claude の SSE そのまま。ヘッダ `x-chat-ticket`（次の呼び出しに付ける札。毎回新しくなる）、`x-chat-rounds-left`（この依頼であと何回呼べるか）、`x-chat-remaining`（今日あと何回頼めるか。最初の呼び出しで数えたときだけ）。
- 失敗: 既存の `/api/ai/*` と同じ `{ error, message }` の JSON に、同じ値の `code` を足した形。`code` は次のどれか。`ai_upstream_error` の返事にも `x-chat-ticket` と `x-chat-rounds-left` が付く（同じ本文のやり直しに使える。最初の呼び出しなら点を使い直さない）。

  | 状態 | code | 意味 |
  |---|---|---|
  | 400 | `bad_request` | 本文の形が違う（JSON でない、`messages` が配列でない・空・最初か最後が `user` でない、送れないブロック、`cache_control`、深すぎる入れ子、など）|
  | 413 | `too_large` | 本文が 160KB を超えた |
  | 429 | `quota_exceeded` | 今日の回数を使い切った |
  | 401 | `ticket_invalid` | 札の署名が合わない・期限切れ・古い札・前の会話に足しただけになっていない |
  | 429 | `rounds_exceeded` | この依頼の往復（8 回）か、送った本文の合計（1MB）の上限を超えた |
  | 503 | `quota_unavailable` | 回数を数えられなかった（止める側）|
  | 503 | `ai_unavailable` | Claude の鍵が無い |
  | 502 | `ai_upstream_error` | Claude が失敗を返した |

- 決めた値: 1回の依頼の往復は最初を含めて 8 回まで、札の有効期限は 10 分（延びない）、チャット1回の点数は 21 点（`env.AI_CHAT_POINTS` で変えられる。今の1人1日 126 点・全体 315 点の枠を読み取りと共有する）、`max_tokens` は 8000、本文は 160KB まで、札ごとに送った本文の合計は 1MB まで、考える深さ（effort）は `env.ANTHROPIC_CHAT_EFFORT`（既定 `medium`）。
