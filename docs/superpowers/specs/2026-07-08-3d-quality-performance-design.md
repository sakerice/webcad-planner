# 3D品質向上・性能最適化・日本住宅規格準拠 設計書

日付: 2026-07-08
対象: webcad-planner(単一 `index.html` 約13,500行、Three.js r128)

## 目的

戸建て住宅の間取り・外観シミュレーションツールとして、
1. 3D描画の動作を軽くする(モバイル/iPad優先。商談利用を想定)
2. 見た目の品質はむしろ向上させる(性能と品質のトレードオフにしない)
3. 配置オブジェクトを日本の住宅規格(飯田グループ系910モジュール、LIXIL建具規格)に準拠させる
4. 施主が意識しないが実在し見た目に影響する住宅設備(雨樋・排水・外部設備)と、光・色の高度な再現でシミュレーションの現実準拠性を高める

制約: 既存機能を壊さない。現在より動作を重くしない。Three.js r128 を維持(案A)。

## 現状診断

### 性能
- `loop3D()` が rAF で毎フレーム無条件レンダリング。アイドル時も SAO+Bloom 込みのフル描画が回り続ける(モバイルは33ms間隔throttleのみ)。iPadの発熱・電池消費の主因。
- `preserveDrawingBuffer:true` が常時有効(スクリーンショット用途)。
- 家具GLBが重い: Sofa01=12.5MB / Washing_Machine=14MB / Sofa02=10MB 等。家具配置済みプランはモバイルで50MB超のダウンロードとGPUメモリ圧迫。
- 壁・建具・アイテムが個別メッシュでドローコール過多。ジオメトリ統合なし。
- pixelRatio は min(dpr,2)。SAO/Bloomがフル解像度で走る。

### 規格
- 準拠済み: 天井高2400 / 910モジュール階段(910×1820) / キッチン2550 / UB1616相当(1600×1600) / 基礎高450。
- 未準拠・未整備: 窓・掃き出し窓にLIXIL呼称サイズプリセットなし(現状一律1650固定)。室内ドア780は良いが規格系列(650/750/780)の提示なし。階段の蹴上げ・踏面が建築基準法値と未照合。

### 3D品質
- GLTF_MAP にない家具は箱型プリミティブのフォールバックで品質が低い。
- ライティングは固定太陽位置+HDR環境マップ。時刻・季節の概念なし。

### 現実準拠ディテール
- 雨樋(軒樋・竪樋)・雨水枡・汚水枡・基礎水切り・エアコン室外機・給湯器・電気メーター等が3D上に存在しない。

## 設計

### ワークストリーム1: 性能最適化(見た目を落とさない)

**1-1. オンデマンドレンダリング**
- `loop3D` を「dirty フラグ制御」に変更。描画するのは以下のときのみ:
  - OrbitControls の `change` イベント発火時(+damping収束まで継続)
  - ウォークスルーアニメーション中
  - シーン再構築(`rebuild3D`)・ビュー切替・ライト変更・テクスチャ/GLB非同期ロード完了時
  - WASD移動キー押下中 / ギズモドラッグ中
- 実装は `invalidate3D()` 関数を追加し、上記イベントで呼ぶ。rAFループは維持するが dirty でない限り `composer.render()` をスキップ。
- リスク: 描画トリガの漏れで「画面が更新されない」バグ。→ テクスチャ/モデルロード完了コールバックからの invalidate を網羅。フォールバックとして低頻度(2秒毎)の保険レンダを1回入れる。

**1-2. preserveDrawingBuffer 廃止**
- `false` に変更し、スクリーンショット(`toDataURL` 3箇所)直前に同期レンダを1回実行してから取得する。

**1-3. GLB軽量化(品質維持)**
- `assets/models/unity_exported/*.glb` のテクスチャを2048→1024pxへ縮小し、JPEG/PNG品質を調整して再パック(pygltflib + Pillow)。ジオメトリはそのまま(形状品質を落とさない)。目標: 合計74MB→20MB以下。
- 見た目検証: 変換前後のスクリーンショット比較で劣化が知覚されないことを確認。
- furniture_mega / interior_model は配信対象を確認し、同様の軽量化はマニフェスト経由でロードされる分のみ対象(段階実施)。

**1-4. ポストプロセス最適化**
- SAOPass の解像度をハーフに(r128 SAOPass の resolution 設定)。saoIntensity は視覚検証しつつ再調整。
- Bloom は現行値維持(既に軽い設定)。
- モバイル(タッチデバイス)ではSAOをオフにする代わり、焼き込み風の接地影(コンタクトシャドウ)や環境光調整で見た目を維持。※見た目劣化が確認されたらSAOハーフ解像度で統一。

**1-5. 静的ジオメトリの整理**
- 壁・床・巾木等、マテリアルが同一の静的メッシュを BufferGeometryUtils 相当のマージでドローコール削減(r128の `THREE.BufferGeometryUtils` examples を追加ロード)。
- ピッキング(クリック選択)は既存の userData 依存があるため、マージ対象は「選択不可能な純装飾ジオメトリ」に限定し、既存の選択挙動を壊さない。

### ワークストリーム2: 日本住宅規格準拠 + 3D品質向上

**2-1. LIXIL窓規格プリセット**
- 窓アイテムに呼称サイズプリセットを追加(プロパティパネルにセレクタ):
  - 引違い: 06903(690×370), 16903(1690×370), 16509(1650×970), 16511(1650×1170), 16513(1650×1370)
  - 掃き出し: 16520(1650×2030), 25620(2560×2030)
  - 縦すべり: 02613(260×1370), 06013(600×1370)
  - FIX/上げ下げ等は必要最小限
- 選択すると w / 高さ / 取付高(掃き出しはFL±0、腰窓はFL+900等)が規格値に設定される。デフォルトは現行値を維持(既存プラン非破壊)。

**2-2. 建具・階段の規格整合**
- 室内ドア系列: 650 / 750 / 780(現行デフォルト780維持)。
- 階段: 蹴上げ≦230mm・踏面≧150mm(建築基準法)+飯田系標準(蹴上げ約200/踏面約210)で3D生成時の段数・寸法を算出。
- 玄関ドア: W940×H2330系(LIXILジエスタ相当)をデフォルト値候補に。

**2-3. 3Dオブジェクト品質向上**
- 箱型フォールバックの主要アイテム(キッチン・ソファ・ベッド・ダイニング等の procedural 版)を、面取り・脚・クッション分割など低ポリでも見栄えする形状に改良。マテリアルは roughness/metalness を実物準拠に調整。
- GLTF_MAP 未登録でGLBが存在するアイテムはマップに追加。
- 窓サッシの見た目をLIXILアルミ樹脂複合サッシ風(フレーム見付寸法・色: シャイングレー/ブラック)に改良。

### ワークストリーム3: 外部設備の自動生成(雨樋ほか)

**3-1. 雨樋自動生成**
- `build3DRoofItem` の屋根形状(切妻・寄棟等)から軒先エッジを抽出し:
  - 軒樋: 半丸105mm相当のチューブを軒先に沿って生成
  - 竪樋: φ60の円柱を建物コーナー(雨樋計画の標準位置)に配置、軒樋から地面へ
  - 雨水枡: 竪樋の足元に小さな枡(150角)を生成
- 生成は roof アイテム単位で自動。表示ON/OFFトグルを外観設定に追加(デフォルトON)。
- ジオメトリは全て低ポリ(チューブ分割数を絞る)で性能影響を最小化。

**3-2. その他の外部設備(自動+一部アイテム)**
- 基礎水切り: 基礎天端に見切りラインを自動生成(細いプロファイル)。
- 配置アイテムとして追加: エアコン室外機 / 給湯器(エコキュート・ガス給湯器) / 電気メーター・引込線位置 / 汚水枡列。低ポリ procedural で作成し、外構カテゴリに追加。

### ワークストリーム4: ライティング・色再現の高度化

- 太陽位置の時刻・季節連動(方位設定と組合せた簡易太陽軌道計算)。UIにスライダー(時刻)+季節プリセット。日当たりシミュレーションとして商談価値が高い。
- 空の色を時刻に応じてグラデーション変更(既存 makeSkyTexture を拡張)。
- 室内照明(light-ceiling 等)の色温度プリセット(電球色2700K/温白色3500K/昼白色5000K)。
- 全て「レンダリングは操作時のみ」の枠内で動くため性能負荷は増えない。

## 実施順序と検証

1. WS1(性能) → 2. WS2(規格+品質) → 3. WS3(外部設備) → 4. WS4(ライティング)

各WS完了時に:
- Chrome(claude-in-chrome)で実機動作確認: 2D/3D切替、家具配置、ウォークスルー、スクリーンショット機能
- 性能はDevToolsでフレーム時間・アイドル時GPU使用を前後比較
- 既存保存データ(localStorage プラン)の読込互換を確認

サブエージェント方針: 独立性の高い作業(GLB軽量化スクリプト、procedural家具の形状改良、規格プリセット表の整備)は Sonnet サブエージェントに委譲し、レンダリングループ変更・雨樋生成など既存コードと密結合な部分は Opus/本体(Fable)が直接実施する。

## 非スコープ

- Three.js のバージョンアップ(案B)
- 家具アセットの総入れ替え(案C)
- furniture_mega / interior_model 全モデルの一括再圧縮(配信されるものだけ段階対応)
- 2D図面側の変更(規格プリセットが2Dに与える寸法変更は除く)

## 成功基準

- アイドル時のGPU/CPU使用が大幅減(描画停止)しつつ、操作時の見た目は現状以上
- 主要家具GLB合計が1/3以下に軽量化、見た目の劣化が知覚されない
- 窓・建具がLIXIL呼称サイズで配置可能
- 屋根に雨樋・竪樋・雨水枡が自動生成され、トグルで表示切替可能
- 時刻・季節で太陽光と空が変化する
- 既存プランの読込・編集・保存・スクリーンショットが全て従来通り動作
