# スキップフロア 設計

作業ブランチ: `worktree-skip-floor`（`.claude/worktrees/skip-floor`、default-plans の c94caaa から分岐）

## 1. 何を作るのか

同じ階の中に、床の高さが違う区画（スキップフロア／中2階／小上がり）を作れるようにする。
実際のスキップフロア住宅で必要になるものまで含める:

- 任意の高さに持ち上がった床と、その**天井も一緒に上がる**こと
- 持ち上がった床の**下にできる空間**と、そこへ**置ける収納（造作棚）**
- 段差の境界を**任意の高さの壁**（腰壁・手すり壁）で仕切れること
- **段差を上り下りする短い階段**（同一階内の数段）と、その**階段下を塞ぐ選択**
- 段差の上に立つ壁が高くなったぶん、**その上に載るものだけ**が持ち上がること

## 2. なぜ既存の「床の高さ」では足りないのか

いま既にあるもの:

| 仕組み | 場所 | 範囲 | 天井 |
|---|---|---|---|
| `room.floorRaiseMm`（床上げ） | `roomFloorOffsetMm` | 0〜600mm | **動かない**（UI にも「天井の位置は固定です」と書いてある） |
| `room.ceiling.heightMm`（天井高） | `HeightModel.ceilingHeightMm` | 任意 | 階の床スラブ天端から測る |
| `plan.floors[階].storyHeight`（階高） | `HeightModel.storyHeightMm` | 任意 | — |
| `wall.wallHeight`（壁1枚の高さ） | `wallHeightMm` | 300〜6000mm | 階の床スラブ**下端**から立つ |
| 局所的な支持 | `localSupportTopY` | — | 下階に既定より高い壁があると、**その上に載る床だけ**が壁の天端まで上がる |

`floorRaiseMm` は「玄関土間 +0 / 室内床 +150」のような**仕上げの段差**で、天井は動かない。
スキップフロアは「その区画ごと床も天井も持ち上がる」ものなので、`floorRaiseMm` の上限を
広げるだけでは意味が変わってしまう。そこで **別のフィールドを足し、床上げとは重ねて効く**
ようにする。既存プランは新フィールドを持たないので、寸法は1mmも動かない。

## 3. データモデル

### 3.1 部屋

```js
room.skipLevelMm    // 0〜2400、50mm刻み。省略=0。この区画の床レベル
```

床仕上げ面の高さ（階の床スラブ下端から）は

```
localSupportTopY(...) + floorSlabHeightMForFloor(floor) + skipLevelMm + floorRaiseMm
```

`skipLevelMm` と `floorRaiseMm` は**足し算**。前者は構造の段差、後者は仕上げの段差で、
小上がり和室（+400 の畳コーナー）の上にさらに +150 を乗せる、といった書き方ができる。

### 3.2 天井の扱い

| 部屋の天井指定 | 天井面の位置（階の床スラブ下端から） | 意味 |
|---|---|---|
| 指定なし | **その部屋の上にある物の下端**（= `roomCeilingCapM`） | 従来は階高固定だった。下の壁が高くて上の床が持ち上がっていれば、そこまで届く |
| `ceiling.heightMm = H` | `slab + skipLevelMm + H` | H は**その区画の床から**測る |
| 勾配 / 吹き抜け | 既存のまま + `skipLevelMm` | — |

```
roomCeilingCapM(room) = max( storyHeightM(floor),
                             localSupportTopY(floor+1, 部屋の矩形) - floorBaseY(floor) )
```

下階に高い壁が無ければ `localSupportTopY` は `floorBaseY` をそのまま返すので、
**cap は階高と完全に同値**になる。つまり既存プランの天井は1mmも動かない。

### 3.3 階高は伸ばさない。上に載るものだけが上がる

`plan.floors[階].storyHeight`（= 家全体の基準面 `floorBaseY`）は**触らない**。
代わりに、既に在る `localSupportTopY`（「下階に既定より高い壁があれば、その上に載る床
だけがその天端まで上がる」）を、段差の上に立つ壁まで見えるように広げる:

```
壁の天端 = 下階の床天端 + wallSkipBaseMm(壁) + wall.wallHeight
```

`wallSkipBaseMm(w)` は、その壁が接している部屋の `skipLevelMm` の最大値
（`wallAdjacentRoomsCeiling` と同じ両側サンプリング）。

これで「1階に +1200 のスキップフロア、その上に 2400 の壁」と書くと、その壁の天端は
3600 になり、**その真上に載る2階の床・屋根だけ**が 3600 へ持ち上がる。家全体の階高も、
段差を作っていない場所の2階の床も動かない。

壁そのものの足元も同じ考えで揃える。壁の平面フットプリントが**すべて**高い支持の上に
在るときだけ、その壁は持ち上がった床から立つ（`wallBaseSupportY`）。一部しか載って
いない壁は従来どおり `floorBaseY` から立てる——持ち上げると載っていない側に穴が開く。
判定を「全部覆われているときだけ」にするのは、既にある `wallStackedAboveCapM` と同じ
考え方である。

**限界として明記する**: 階の中でレベルは分かれるが、`floorBaseY(floor)` は階に1つの
ままである。つまり「2階の一部だけが半階ずれた家」を作るときは、2階側の部屋にも
`skipLevelMm` を書く（各階が自分の中でレベルを持つ）。

### 3.4 壁

壁は従来どおり `floorBaseY(階)` から立つ（段差の蹴上げ面を兼ねるので、下ろさないと
低い側に穴が開く。例外は 3.3 の「全部が高い支持に載っている壁」）。変えるのは**上端**:

- 個別指定なし: `wallCeilingHeightM` が接する部屋の天井高の最大を採る。
  3.2 で天井が上がれば壁も自動で伸びる。**変更不要**。
- 個別指定あり（腰壁1100 など）: `wallDisplayHeightM` を
  `wallSkipBaseMm(w) + wallHeight + slab` にする。
  段差の縁に立てた手すり壁が、持ち上がった床から 1100mm になる。

### 3.5 階段

```js
item.stairTarget  // 'upper'(既定/省略) | 'level'
```

- `'upper'`: 従来どおり。上階の床まで上がる。段数も従来どおり `FLOOR_H` から出す
  （ここを実際の上り高さに変えると既存プランの段数が動くので触らない）。
- `'level'`: **同じ階の中の段差**を上る。
  - 上り高さ = 階段グループの走行軸の両端 300mm 外側で `roomFloorAt` を採り、その差。
    差が 50mm 未満なら「その階の最大 skipLevel − 足元のレベル」を代わりに使う。
  - 足元は低い側のレベル。段数は実際の上り高さから `stairStepCount` で出す。
  - 上階の床に**吹き抜け穴を開けない**（`stairwellQuadsForFloor` から除外）。
  - 同じ階の持ち上がった床と平面で重なるときは**その床を開ける**。
    穴（`ExtrudeGeometry` の hole）としては開けない。THREE は外形と穴の壁を
    別々に作るので、穴が外形の辺に接しても外周の壁が切れず、段差の小口が
    1枚の板として階段を横切る（実際にそうなり報告された）。段差の天板は
    **矩形の差**（`subtractRectsFromRect`）に割って作り、面を本当に途切れさせる。
    開口が軸に沿った矩形にならない（回した階段）ときだけ従来の穴の経路へ落ちる。
  - ウォークスルーでは階を変えずに足元だけ坂面化する。

### 3.6 段差の下の空間、柱、造作棚

`skipLevelMm + floorRaiseMm` が 400mm 以上ある部屋では、床下を**中空**にする。
400mm 未満（小上がり）は使える空間にならないので従来どおり solid のまま。

**アプリはこの空間を塞がない。** 床下を壁で囲うのか、柱で持たせるのか、奥の壁を
支えにして手前を開けるのかは設計そのものなので、置くのは利用者である。
自動で立ち上がり（蹴上げ面）を作ると、引いた覚えのない壁が現れる
（実際にそうなり、「奥に壁ができる」として報告された）。囲う手段は既にある壁
（高さは `wallSkipBaseMm` により持ち上がった床から測る）と、新しく足す柱。

新しい種類 `column`「角柱」/ `column-round`「円柱」（部屋・壁メニュー）:

- 太さは幅・奥行き（既定 180mm 角 / 径180mm）、高さ `columnHeight`（既定 2400mm）。
- 段差のある部屋の中へ置くと、足元がその階の構造床へ下り
  （`baseLevel='under'`）、高さが段差の寸法へ合う。毎回入力させるものではない。

収納は置くアイテムにする。新しい種類 `shelf-built-in`「造作棚」:

- 棚板の枚数 `shelfCount`（1〜8、既定3）、全体高さ `shelfHeight`（既定 900mm）、板厚 25mm。
- 縦板の有無 `shelfSides`: 省略=自動 / `'none'` 縦板なし（壁が支える）/ `'both'` 両端に縦板。
  自動は「背面が壁の面から 140mm 以内、幅方向が壁と15度以内で平行」で判定するが、
  回転や反転を掛けた棚では当てにくい。**自動だけにすると「縦板の無い棚が作れない」
  状態になる**ので、明示が自動より優先する。

段差の下へ置くための基準:

```js
item.baseLevel   // 'floor'(既定/省略) | 'under'
```

`'under'` のアイテムは、その部屋の持ち上がった床ではなく**その階の床天端**に置かれる
（= 段差の下の空間に入る）。段差のある部屋の中に居るアイテムにだけ、プロパティ欄に
この選択を出す。

### 3.6b 天井付けの器具は天井について動く

天井が動く操作は、段差・床上げ・天井高・天井の種類と複数ある。**どれか1つだけを
直しても、残りで器具が取り残される**（実際に「ライトが天井に追従していない」と
して報告された）。書き込む側を1か所へ寄せ、`followRoomCeiling` / `updateSelectedProp`
から `shiftRoomCeilingFixtures` を通す。

保つのは **天井からの下がり**である。天井に直付けのものは直付けのまま、意図して
下げてあるペンダントはその下がりのまま動く。`elev` は仕上げ床からの値なので、
動かす量は「床から天井までの高さ」の差そのものになる。

天井の上限（3.2 の `roomCeilingCapM`）が階高を超えてよいのは、**自分が段差を
持っている部屋だけ**にしてある。`localSupportTopY` は「矩形を跨ぐ下階の壁の最大」
なので、段差を持たない部屋にまで広げると、境界の壁が1本高いだけで隣の部屋の
天井まで上がり、そこに既に付いている照明が取り残される。

### 3.6c 段差の上に立つ壁

```js
wall.baseLevel   // 省略=自動 | 'floor' 階の床から | 'skip' 段差の上から
```

段差の下は中空なので、段差の上に立つ間仕切り壁の足元を上げないと、板が床下へ
垂れ下がる。**両側とも段差の上にある壁だけ**足元を上げる（`wallSkipFootMm`）。
片側でも低いレベルに面していれば下ろしたまま——その壁は蹴上げ面を兼ねており、
持ち上げると低い側の足元に穴が開く。高さを測る基準は従来どおり**高い側**
（`wallSkipBaseMm`）で、段差の縁の手すり壁が持ち上がった床から測られる。

自動判定は接する部屋のサンプリングなので、部屋の外を通る壁や縁からわずかに
外れた壁では当たらない。そのための明示が `baseLevel` である。

### 3.7 階段の手すり

```js
item.stairRail       // 'none'(既定/省略) | 'left' | 'right' | 'both'
item.stairRailMount  // 省略=自動 | 'wall' 壁付け | 'post' 柱建て
```

付ける側は平面からは決まらないので利用者が選ぶ。壁付けか柱建てかは、その側に
階段と平行な壁が沿っているか（`stairSideHasWall`：15度以内で平行、側面線から
250mm 以内、走行の半分以上に重なる）で決める。造作棚と同じ考え方で、**自動
だけにすると作れない納まりが出る**ので明示が優先する。

手すりは段鼻から 800mm。走行の形は階段の種類で違うので、
**踏板の段鼻を結んだ点の列**を階段の側から渡し、`build3DStairRails` が金物と
木部を組む。直階段は一直線、廻り階段は外周の折れ線（左）と内隅（右）。

丸棒を並べただけの作りは実物に見えない。**断面を走行に沿って押し出す**
（`ExtrudeGeometry` ＋ `Matrix4.makeBasis`）ことで、笠木も桟も勾配なりに
1本で通る。角は丸めた矩形断面（`stairRailRoundedRectShape`）で、真四角の
角材にはしない。

納まり:

- 壁付け … 笠木 40×55 の丸めた矩形断面。端部は壁側へ返す。
  ブラケット（壁プレート・アーム）900mm 間隔。
- 柱建て … 笠木 62×38（木）＋ 支柱 40×12 のフラットバー（金物）を
  950mm 間隔。あいだの意匠は下の共通語彙で選ぶ。

**子柱と親柱の丈は、その位置の手すり芯から逆算する**（`railPolylineYAt`）。
定数で出すと斜めの手すりに対して最大で蹴上げの半分ずれ、届かない子柱と
突き抜ける子柱が混ざる。子柱は**踏板1枚の中**で分ける。点の列は踏板の
**中央**を結んでいるので、点と点のあいだで分けると区間の後半がもう次の段に
入り、手前の段の高さで立てた子柱が次の踏板を下から貫く（実際そうなり
「手すりの縦棒が横板を貫いている」として報告された）。踏面の奥行きは前後の
点との間隔から採り、その中に内法 110mm 以下になる本数を並べる。

### 3.7b 手すりと格子柵は同じ語彙で選ぶ

階段の手すりと格子柵は、実物では同じ部材である（笠木・支柱・そのあいだの
意匠）。設定の言葉を分けると、同じ家の中で手すりだけ浮く。**どちらも同じ
フィールドで決める**。

```js
item.railInfill     // 'bars'(横桟) | 'wires'(横ワイヤー) | 'baluster'(縦格子) | 'none'
item.railBars       // 横桟の本数。省略=3
item.railCapColor   // 笠木(木)の色
item.railFrameColor // 骨(支柱・桟・ワイヤー)の色
```

- `'bars'` … 30×8 のフラットバーを等間隔に。既定の本数は3。
- `'wires'` … φ9 の丸鋼。内法 110mm 以下になる本数を自動で決める。
- `'baluster'` … 親柱 80角＋子柱 28角の木の縦格子。
- `'none'` … 笠木と支柱だけ。

省略時は、それぞれの部材が**これまで持っていた見た目**へ落ちる
（`railInfillOf`）。階段の手すりは横桟、格子柵は `fencePattern` から
縦格子／横桟へ写す。骨の色（`railFrameColorOf`）は**明示されたときだけ**
返し、省略時は `null` — 呼び出し側が部材ごとの既定（階段は黒い金物、格子柵は
木）を使う。保存済みのプランの見た目を1mmも変えないためである。

設定の欄は `railingDesignHtml` が1つ作り、階段の手すりと格子柵の両方から
同じものを呼ぶ。欄を2つ書くと、片方だけ増えて語彙がずれる。

```js
item.stairRailColor  // 旧フィールド。railCapColor が無ければこれを読む
```

手すりの部材は `userData.ownColor` を持ち、アイテム色の一括適用
（`applyItemColorToGroup`）から外れる。実物でも手すりだけ樹種や色を変えるのは
普通で、階段の色を変えた瞬間に手すりまで同じ色になるのは作りとしておかしい。

階段の板（踏板・蹴込み板・踊り場）は `canSetItemTexture` に入れ、テクスチャを
貼れるようにした。画像トリミングの欄だけ出て貼る先が無い状態だった。

### 3.8 階段の形状・足元・部材

WOODONE の分類（直・かね折れ・折り返し・回り・らせん・カーブ／箱型・スケルトン・
ひな壇・片持ち）に合わせて整理する。**昇降の形**は置く部材の組み合わせで決まり、
**外観の形状**は1枚ごとの作りである。

部材: `stair` 直進 / `stair-corner` 廻り段 / `stair-landing` 踊り場（新規）。
これで 直階段・かね折れ（L字）・折り返し（U字）・回り階段が組める。
らせん・カーブは未対応。

```js
item.stairStyle   // 'open'(既定/省略) ひな壇 | 'box' 箱型 | 'skeleton' スケルトン
item.baseLevel    // 省略=自動 | 'floor' 階の床から | 'skip' 段差の上から
```

- `'box'` は階段下を塞ぐ（旧 `stairUnder:'filled'` も箱型として読む）。
- `'skeleton'` は蹴込み板を張らない。光と視線が抜けるのがこの形の目的である。
- 片持ちはこのモデルでは スケルトンと見分けがつかないので持たない。

**足元は「下端の先にある床」から採る**。部材の中心で採ると、段差の上から始まる
階段が、footprint の中心が段差からはみ出しただけで低い側から始まってしまう
（2730mm の直階段は小さな段差に収まらないので普通に起きる。実際そうなり
「階段のスタート位置をスキップフロアにできない」として報告された）。
下端の先にも部屋が無いときだけ各部材の中心から採り、`baseLevel` の明示が
それより優先する。

### 3.8b 格子柵を手すりに使う

```js
item.latticePitch // 格子の間隔(mm)。省略=95
item.latticeSlat  // 格子の見付(mm)。省略=55
item.latticeCap   // 笠木。省略=なし
```

もとは外構の目隠しだが、スキップフロアや吹き抜けの手すりにも使える。
手すりとして使うには、格子の内法（子どもがすり抜けない 110mm 以下が目安）と、
掴める笠木が要る。既定値は従来の見た目のままで、明示したときだけ変わる。
意匠と色は 3.7b の共通語彙（`railInfill` / `railCapColor` / `railFrameColor`）で
階段の手すりと同じものを選ぶ。`railInfill` を明示すると、従来の『格子方向』
（`fencePattern`）より優先する。欄には「指定しない」を残し、従来の見た目へ
戻れるようにしてある。
併せて、**部屋の中に置かれた接地物（格子柵・塀・樹木など）は、地面ではなく
その部屋の床（段差の上を含む）に立つ**ようにした。

### 3.9 階段の下

```js
item.stairUnder   // 'open'(既定/省略) | 'filled'
```

階段は踏板と蹴込み板だけで作ってある（スケルトン階段）。実際の住宅では階段下を
塞いだ箱型の方が多く、塞げば階段室の空気が上下階で素通しにならない。
どちらにするかは設計なので選ばせる。**省略時は従来どおり素通し**で、保存済み
プランの階段は1枚も増えない。直階段は段ごとに足元から踏板の下面まで、
廻り階段は踏板の形のまま足元まで下ろす。仕上げは木ではなく内装色にそろえる。

階段下を収納にしたいときは、埋めずに造作棚を置く（塞ぐと中に入らない）。

### 3.10 レベル階段の向き

階段は常に**自分のローカル +奥行き方向**へ上る（3Dの段も2Dの踏み板線も）。
両端の高さの min/max だけを見ると、逆向きに置かれた階段が「最上段の踏板から
始まる」形で描かれる（実際にそうなり、「立板からでなく横板から始まる」として
報告された）。`stairLevelSpanM` は階段自身の向き（rot / flipY）で低い側・高い側を
判定し、逆を向いていれば `reversed` を立てて**段を積む向きだけ**を合わせる。
平面上の位置は動かさない（利用者が置いた場所は変えない）。

## 5. 検査

新規 `tools/tests/skip-floor.test.cjs`（既存テストと同じ node:vm 方式）:

1. `skipLevelMm` を持たない部屋は、床天端・天井・階高・壁高が**1mmも動かない**
2. `skipLevelMm=1200` の部屋の床天端が +1200 になる（床上げと足し算になる）
3. 天井高を明示した段差部屋で、天井が段差ぶん一緒に上がる
4. 段差の上に立つ壁の天端が `段差 + 壁高` になり、その上に載る床だけが上がる
5. 一部しか高い支持に載っていない壁は、足元が `floorBaseY` のまま
6. 腰壁（`wallHeight=1100`）が段差の上から 1100mm になる
7. `stairTarget='level'` の階段の上り高さが段差と一致し、段数がそれに追従する
8. `stairTarget='level'` の階段は上階の床に穴を開けない
9. `baseLevel='under'` のアイテムが段差の下（その階の床天端）に置かれる
10. 造作棚の縦板は、明示（`shelfSides`）が自動判定より優先する
11. アプリは段差の立ち上がりを1枚も作らない
12. レベル階段は、置き方によらず低い側から高い側へ上る（`reversed` の検出）
13. 柱は角柱と円柱に描き分け、段差の下へ置くと高さが段差に合う
14. 階段の下は省略すれば素通しのまま、`'filled'` で直階段も廻り階段も塞ぐ
15. 段差を持たない部屋の天井は、隣の壁が高くても階高のまま
16. 天井が動くと、天井付けの器具は天井からの下がりを保ったまま動く
17. 矩形の差が正しく割れ、段差の天板は開口で外周面も途切れる
18. 両側とも段差の上の壁だけ足元が上がり、境界の壁は下ろしたまま
19. 壁の基準（`baseLevel`）の明示が自動判定より優先する
20. 手すりは省略すれば付かず、左右を選べ、壁が沿っていれば壁付けになる
21. 手すりの付け方の明示が自動判定より優先する
22. 踊り場は段を持たず、手前までの段が積み上がった高さに座る
23. 上り高さは、種にした部材で変わらない（折り返しでも同じ）
24. 段差からはみ出す大きさの階段でも、足元は段差の上から始まる
25. 階段の形状（箱型/ひな壇/スケルトン）と足元の明示が効く
26. 格子柵の間隔・見付・笠木が選べ、既定は従来の見た目のまま
27. 折れ線の高さを内挿でき、子柱・親柱の丈がそこから出る
28. 子柱は自分が立つ踏板の中だけに収まり、隣の踏板を貫かない
29. 手すりの色は階段の板とは別に持て、アイテム色に塗り潰されない
30. 階段の板にテクスチャを貼れる
30b. 手すりは断面の押し出しで作り、丸棒の羅列にならない
30c. 意匠（横桟・横ワイヤー・縦格子・桟なし）と笠木／骨の色が、
     階段の手すりと格子柵で同じフィールド・同じ欄から選べる
30d. 省略時は、それぞれの部材のこれまでの見た目へ落ちる
31. `plan-schema` が新フィールドの範囲外を警告として挙げる

既存の全単体検査（`sh tools/run_tests.sh`）と描画の指紋
（`sh tools/run_browser_tests.sh render-fingerprint`）が通ることを完了条件にする。

## 6. やらないこと

- 階そのものを半階ずらすモデル（`floorBaseY` の分岐）。3.3 の限界として明記する。
- スキップフロアを跨ぐ屋根・斜線制限の特別扱い。壁が高くなれば `localSupportTopY` 経由で
  屋根の足元は追従する。
- 段差の自動検出（「隣り合う部屋の高さが違うから階段を置く」）。置くのは利用者。
