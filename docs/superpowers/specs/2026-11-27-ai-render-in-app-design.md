# AIレンダーをアプリの中で生成する 設計書

2026-11-27。利用者が 2026-11-26 に「アプリ内で生成する」と決め、2026-11-27 に画像 AI・上限・動画の扱いを決めた。

## 何のために作るか

今の AIレンダーは「画像AI用データ」（ガイド画像 6 枚と指示文の ZIP）を保存させるところで終わっていて、仕上がった絵を見る画面が無い。利用者は自分で外の画像 AI に持ち込まないと結果を見られない。
3D の画面から 1 回押すだけで、写真のような絵がアプリの中に出て、保存できるようにする。App Store のスクリーンショットにもこの結果の画面を使う。

## 目標・やらないこと・失敗とみなすこと

目標は次のとおり。

- 外観3D・内観3D・ウォークスルーのどれからでも、今の視点の絵を生成し、アプリの中で見て保存できる。
- 画面（ボタン、同意、待ち、結果、保存、失敗の文、報告）まで含めて完成とする。
- 回数と金額の上限を既存の仕組み（Durable Object `AiQuota`）に載せる。

初版でやらないこと。

- 動画の生成。動画は今の「動画AI用データ」の保存のまま残す。
- 利用者が自由に書いた文を生成に送ること。今の「任意の仕上げメモ」は「画像AI用データ」にだけ効き、アプリ内の生成には送らない。
- 生成した絵をサーバーに保存すること、他の利用者に見せること。

失敗とみなすこと。

- 間取り（壁・窓・建具・家具の位置と数）が変わった絵が普通に出てくる。
- 既存の保存プランが開けなくなる。今の「画像AI用データ」の保存が使えなくなる。
- 画面に費用・トークン・秒数・モデル名が出る。

## 決まったこと（利用者の決定）

- 画像 AI は Google の Gemini 画像モデル `gemini-nano-banana-2.1`（Vertex AI）。
- 上限は 1 接続元 1 日 5 枚、全体 1 日 30 枚。間取りの読み取りの点数とは別に数える。
- 初版は静止画だけ。

## 比べた方法

2026-11-26 に、既定の 2 階建ての 1 階 LDK と 2 階主寝室の同じ 3D 画面から各 1 枚ずつ生成して比べた。

| 候補 | 待ち時間 | 1 枚の費用 | 結果 |
|---|---|---|---|
| Vertex AI `gemini-nano-banana-2.1` | 18〜24 秒 | 約 $0.045 | 窓・扉・家具の数と位置がいちばん保たれた。採用 |
| Vertex AI `gemini-3.1-flash-image` | 8〜9 秒 | 約 $0.069 | 扉を消して奥に部屋を描き足した |
| Workers AI `flux-2-klein-9b` | 7〜10 秒 | 約 $0.017 | 画角は保つが、レンジフードなどが別の物に置き換わった。入力は 512px 未満 |
| OpenAI `gpt-image-2.6-flare` | 試せていない | 公表値 $0.03〜0.14 | 登録済みの鍵が無効だった |

4 社のどれにも、深度や線画で構図を固定する専用の機能（ControlNet の類）は残っていない。採用した方法は、3D の絵に深度と線画を添え、指示文で「形を変えない」と頼む方式である。

同じモデルでの出し方の差も確かめた。

- 3D の絵だけを送ると、椅子が 1 脚増え、窓の形が変わった。深度と線画を添える。
- 短い指示文は明るく生活感が出るが、IH がガスコンロに、扉が木目に変わった。
- 今のアプリの長い指示文（`buildAiRenderPrompt`）は色と設備まで元に忠実で、小物を足さなかった。ただし暗い。
- 出力の縦横比は決まった種類からしか選べず、3:2 で頼むと 16:10 の入力より写る範囲が広がった。

## 全体の流れ

1. 利用者がヘッダーの「AIレンダー」を押す。ダイアログが開く。
2. 「写真のように仕上げる」を押す。初めてのときは、送るものと送り先を示す同意の画面が出る。
3. アプリが今の視点の 3 枚（3D の絵・深度・線画）を撮り、縦横比を合わせて縮め、Worker の `POST /api/ai/render` に送る。
4. Worker が出どころと上限を確かめ、指示文を組み立て、Vertex AI を呼び、絵を返す。
5. アプリが結果を表示する。利用者は元の 3D と見比べ、保存し、もう一度生成し、問題があれば報告できる。

## Worker 側

### `POST /api/ai/render`

リクエスト（JSON）。

```json
{
  "preset": "life",
  "view": "interior",
  "aspect": "3:2",
  "images": { "base": "data:image/jpeg;base64,…", "depth": "data:image/jpeg;base64,…", "edge": "data:image/jpeg;base64,…" }
}
```

- `preset` はアプリの `AI_IMAGE_PRESETS` のキーに対応する決まった値だけを受ける。知らない値は 400。
- `view` は `interior` か `exterior`。
- `aspect` は採用モデルが受ける縦横比のうち Worker が許す一覧にあるものだけ。
- `images` の 3 枚は JPEG か PNG の data URL。1 枚あたり 3MB（base64 の文字数）まで、3 枚とも必須。
- これ以外の欄は読まない。**文章の欄は受け取らない。** 指示文は Worker が `preset` と `view` から組み立てる。画面を通さずに API を直接呼ばれても、任意の絵を作る道具として使えないようにするためである。

応答。

```json
{ "image": "data:image/png;base64,…", "remaining": 4 }
```

`remaining` は、その接続元が今日あと何枚生成できるか。

エラー。既存の形（`{error, message}`）に合わせる。

| 場合 | status | error |
|---|---|---|
| 出どころが許可外 | 403 | `forbidden_origin` |
| 入力がおかしい | 400 | `bad_request` |
| 上限に達した | 429 | `ai_quota_exceeded`（`scope` は `user` か `total`、`message` は利用者向けの日本語） |
| 数えられない | 503 | `ai_quota_unavailable` |
| AI が安全上の理由で絵を返さなかった | 422 | `render_blocked` |
| 上流の失敗・時間切れ・絵が返らない | 502 | `ai_upstream_error` |

上流のエラー本文はそのまま返さない（鍵の一部が入ることがある）。

### 指示文

`worker/render-prompt.mjs` に置く。土台は今の `buildAiRenderPrompt` の「Strict requirements」と「Negative prompt」の考え方（形を変えずに質感だけ上げる）で、忠実さを優先する。そこに、試し生成で暗かった点を補う文（自然な昼の光、明るい露出）を足す。

- 1 枚目は 3D の絵、2 枚目は深度、3 枚目は輪郭線だと説明する。
- カメラ・壁・窓・建具・家具・設備の位置と大きさと数と種類を 1 枚目と一致させる。足さない・消さない・動かさない・別の物に置き換えない。画面の端で切れている物もそのまま残す。
- 人物・文字・透かしを入れない。
- `preset` ごとの表現の文（実写、水彩など）は Worker 側に持つ。
- 利用者の文は入らない。

指示文の最終形は、実装の中で既定の 2 階建ての LDK と主寝室で生成して決める（実装者に任せる）。確かめる点は、画面の端の扉が残ること、IH や扉の色が変わらないこと、暗すぎないことの 3 つ。

### Vertex AI の呼び出し

- `worker/vertex.mjs` は今、日本国内のリージョンだけを通す。レンダー用に、場所 `global` を使う呼び出しを別に足す。既存の読み取りの経路の制限は変えない。
- 認証は既存の `worker/google-auth.mjs`（`GOOGLE_SERVICE_ACCOUNT_JSON`）を使う。新しい secret は要らない。
- モデルは環境変数 `AI_RENDER_MODEL`（既定 `gemini-nano-banana-2.1`）。
- `generationConfig` は `responseModalities: ["IMAGE"]`、`imageConfig: { aspectRatio, imageSize: "1K" }`。Google Search による根拠づけは使わない（記録が残るため）。
- 絵は `candidates[0].content.parts[].inlineData` から取る。`finishReason` が `IMAGE_SAFETY` などの安全上の停止、または `promptFeedback.blockReason` があれば `render_blocked`。
- 上流の待ちは 90 秒で切る。

### 上限

- `AiQuota` の別の pool（`render`）で数える。既定は 1 接続元 1 日 5 枚、全体 1 日 30 枚。環境変数 `AI_RENDER_DAILY_PER_USER` / `AI_RENDER_DAILY_TOTAL` で変えられる。読み取りの点数（168 / 700）は減らない。
- 金額の枠（月 $80、1 日の額）は既存のものを共有する。呼ぶ前に 1 枚の最悪の額を仮押さえし、返事の `usageMetadata` で精算する。`worker/ai-price.mjs` に単価を足す（入力 $1.5/M、画像出力 $30/M、文字と思考 $7.5/M。2026-11-26 に Gemini API の料金ページで確かめた値。Vertex AI でも同額かは確かめていない）。
- 全員が上限まで使った場合の額は、30 枚 × 約 $0.045 × 30 日で月 $41 ほど。
- 上流が失敗した・安全上の理由で止まったときは、回数を戻す（既存の仕組みに戻す手段がある場合）。無ければ数えたままにして、設計書のここに書き足す。
- `GET /api/ai/quota` に、レンダーの残り枚数を足す。

### `POST /api/ai/render-report`

生成した絵に問題があったときの報告を受ける。App Store 審査指針 1.2（AI で内容を作るアプリは、不適切な内容を報告する手段を持つこと）への備えである。

- リクエストは `{ reason, image }`。`reason` は決まった選択肢（`inappropriate`、`wrong_layout`、`other`）。`image` は報告する絵（利用者が「絵も送る」を選んだときだけ）。
- R2（`PLANS` バケット）の `render-reports/<日付>/<乱数>.json` に、時刻・理由・絵を書く。接続元の IP は書かない。
- 1 接続元 1 日 10 件まで。
- 運営者は `npx wrangler r2 object get` か Cloudflare のダッシュボードで見る。届いたことを知らせる仕組みは初版に無い（持ち越し）。

## 画面側

### 入口とダイアログ

- ヘッダーの今のボタン（`#unity-render-toolbar-btn`）と今のダイアログ（`#unity-render-modal`）を使う。ダイアログの題は「AIレンダー」にする。
- ダイアログの上から順に、表現の選択（今のプリセット）、主ボタン「写真のように仕上げる」、結果、の順に置く。今の「画像AI用データ」の一式（仕上げメモ、データ作成、ガイド画像、保存リンク）は、その下の「画像AI用データを保存する（ほかの画像AIで使う）」という折りたたみに入れ、動きは変えない。
- 主ボタンの近くに「今日はあと◯枚」を出す。

### 同意

- 初めて生成するとき、同意の画面を出す。書くことは、送るもの（今見ている 3D 画面の絵と、その奥行き・輪郭の絵。選んだ表現の種類）、送り先（Google の画像生成 AI。処理は日本国外）、Google は送った絵を AI の学習に使わないこと、送らないもの（図面の原本、氏名、住所、仕上げメモ）。
- 「同意して仕上げる」「やめる」。同意は端末の localStorage に版つきで残す（プランのデータには入れない）。文面を変えたら版を上げ、もう一度聞く。
- ダイアログの中に「AI への送信の同意を取り消す」を置く。取り消すと、次に生成するときにもう一度聞く。

### 撮る・送る

- 撮るのは今の関数（`captureCurrent3DDataUrl`、`captureAiOverrideGuideDataUrl('depth')`、`makeEdgeDataUrlFromSegmentation`）。「画像AI用データ」と同じ絵である。
- 画面の縦横比に最も近い、モデルが受ける縦横比を選び、3 枚とも同じ範囲を中央で切り抜いてから、長辺 1536px の JPEG に縮めて送る。出力と入力の写る範囲をそろえるためである。iPhone の縦画面なら縦長の比になる。
- 3D でない画面で押したときは、今と同じく外観3D に切り替える。

### 待ち・結果・失敗

- 待っている間は、ダイアログの結果の場所に、撮った 3D の絵を薄く出し、「写真のように仕上げています。そのままお待ちください」と動く表示を出す。主ボタンは押せなくする。秒数は出さない。
- 結果は、ダイアログの幅いっぱいに絵を出す。その下に次を置く。
  - 「元の3Dと見比べる」。押している間（または切り替えで）元の 3D の絵に替わる。
  - 「画像を保存」。iOS では共有シート（`navigator.share` にファイルを渡す）を先に試し、使えなければ今の保存リンクと同じ blob: の保存にする。
  - 「もう一度仕上げる」。
  - 「問題を報告」。理由を選び、「この絵も送る」を選んで送る。
  - 注記「AI が仕上げた絵です。細部が実際の間取りと違うことがあります。」
- 結果の絵はメモリに持つだけで、プランにも端末にも自動では保存しない。ダイアログを閉じて開き直しても、ページを読み直すまでは最後の 1 枚が残る。
- 失敗の文は利用者の言葉で書く。上限（「今日の分は使い切りました。明日また使えます」の趣旨。Worker の `message` をそのまま出す）、混雑（全体の上限）、通信の失敗、AI が絵を返さなかった（「この画面は仕上げられませんでした。視点を変えてお試しください」）、数えられない。どれも「もう一度」か「閉じる」で戻れる。

### 崩れないこと

- iPad Pro 第 2・3 世代（下限端末）と iPhone の縦画面で、結果の絵・ボタン・報告の画面がはみ出さず、指で押せる大きさであること。
- 縦長の絵でも、ダイアログの中でスクロールして全体が見えること。

## 送るデータ（プライバシーの申告に使う）

- 送り先は Google（Vertex AI、場所は global。日本国外で処理される）。
- 送るのは、今の視点の 3D の絵・深度の絵・輪郭の絵の 3 枚と、Worker が組み立てた指示文。利用者の文、図面の原本、氏名、住所、プランのデータは送らない。
- Google は送った絵を学習に使わない。キャッシュは 24 時間以内に消える（Vertex AI の公式文書、2026-11-26 に確かめた）。
- 生成した絵には SynthID の透かしが入る。
- Worker は絵を保存しない。例外は、利用者が「問題を報告」で絵を送ったときだけ。
- 回数を数えるために、接続元の IP（IPv6 は /64）を当日分だけ `AiQuota` に持つ。これは既存の読み取りと同じ。

## App Store 審査への備え

- 5.1.2(i)（第三者の AI に個人データを共有するときは明示して同意を得る）。初回の同意の画面で満たす。
- 1.2（AI で内容を作るアプリの、ふるい分け・報告・連絡先）。ふるい分けは、指示文を Worker が組み立てて利用者の文を受け取らないことと、Google の安全フィルタで行う。報告は「問題を報告」。他の利用者がいないので、利用者をブロックする機能は対象が無い。連絡先はストアの掲載に載せる（PR #158 の側）。
- あとで自由入力を足すときは、審査を通してからにする（2.5.19）。

## 検査

- Worker の単体の検査（`sh tools/run_tests.sh`）。知らない preset・文章の欄・大きすぎる絵を断ること、上限で 429 になること、安全上の停止が `render_blocked` になること、上流のエラー本文を返さないこと、読み取りの点数が減らないこと。Vertex は fetch を差し替えて試す。
- ブラウザの検査（headless）。`/api/ai/render` を差し替えて、同意、待ち、結果、見比べ、保存、報告、各失敗の文、同意の取り消しを通す。iPhone の縦と iPad の大きさで、はみ出しが無いことを確かめる。既存の ai-render-* の検査が通り続けること。
- 手元の Worker（`wrangler dev`、鍵は `tools/link_dev_vars.sh` で渡し、中身は見ない）で、`?preset=2f` の内観 3D から本物の 1 枚を生成し、結果の画面を撮る。

## 実装者に任せること

- 指示文の最終形、縦横比の一覧、要素の id と CSS、検査の名前。
- 新しい画面側のコードは `assets/js/` の別ファイルに置き、`index.html` に足すのは HTML と呼び出しだけにする（`index.html` は大きいので）。`build.sh` と `_headers` に足すものがあれば足す。

## 持ち越し

- 報告が届いたことを運営者に知らせる仕組み。
- OpenAI の鍵が無効（読み取りの予備の経路も働いていない）。利用者が差し替える。
- 動画の生成。
