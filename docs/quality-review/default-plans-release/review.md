## 通り芯からのずれの修正（リリース後）

受領版に残っていた配置検査の指摘9件のうち、設計判断ではなく通り芯からのずれ
だったものを直した。間取り（部屋の並び・家具・仕上げ）は変えていない。
変更は `tools/default_plan_2f_review.py` の `apply_joint_fixes` にあり、
生成スクリプトの最後で当たる。受領原本 `user-plan-25.json` は記録として
そのまま残し、そこからの差が下記3か所だけであることをテストで押さえている。

| 直したもの | 前 | 後 | 指摘 |
| --- | --- | --- | --- |
| 壁1014の南端 | y=3100 | y=3040 | 32（直交する壁1016の芯を厚み半分行き過ぎ、交差部に段差） |
| 階段室r1027の奥行 | 3690 | 3640 | 6（ホールと910×20mm重なり） |
| ホールr1030の位置・奥行 | y=3070 d=1790 | y=3040 d=1820 | 同上 |
| 建具1243の位置・向き | x=6116 rot=0 | x=5980 rot=90 | 1・41・42（壁1013の芯から136mmずれ、開口を壁が254mm横切る、ホール側の有効幅280mm） |

いずれもモジュール線 y=3040 と壁芯 x=6370 へ戻すだけで、ずれの量と向きが
ドラッグの取りこぼしと一致する。建具の向きは、この家と3階建てプランにある
縦壁の `door-swing` がすべて rot=90 である規約に合わせた。

描画側は建具を最寄りの壁へ寄せて描くため画面には出ていなかったが、データ上は
壁が開口を横切ったままで、ユーザーがこの建具に触れた時点で壁との関係が崩れる。

残る指摘4件（17 窓上端の通り・18 収納率・23 キッチン通路・36 ワークトライアングル）
は受領版の設計判断なので触っていない。修正後の検査結果は
`plan25-lint-after-joint-fixes.txt`。

検証: Node 56件・lint自己検査・Python 16件すべて通過。2階建てを平面図・
俯瞰・ウォークスルーで確認し、建具が壁1013の芯に乗ってホール側へ開くこと、
階段とホールの境界が y=3040 で通ることを実測した。3階建ては変更していない。
