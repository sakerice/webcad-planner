# 既定プラン品質チーム — 体制とレビュー運用

目的: house-planner mobile の既定プランを「数億円の家づくりでこのサイトを
選ぶ理由になる」品質に引き上げ、維持する。

## 体制 (`.claude/agents/` に定義)

| 役割 | エージェント | 責務 |
|---|---|---|
| 全体統括 | hc-orchestrator | 最高の注文住宅ホームコンサルタント。ラウンド計画・採否・ロールバック判断 |
| 調査 | research-housing-design | 住宅総合デザイン(外観・構成)の定石とクオリティライン |
| 調査 | research-interior | インテリア(家具・スタイリング・生活感)の定石 |
| 調査 | research-floorplan | 間取り・動線・寸法の定石 |
| 調査 | research-color-material | 外装/内装のカラー・素材マネジメント |
| 実装 | plan-implementer | tools/make_default_plan_2f.py と plan JSON の実装 |
| 評価 | review-interior-design | インテリアデザイン審査(暮らしの説得力) |
| 評価 | review-space-design | 空間デザイン審査(3D目線での納まり・見えがかり) |
| 評価 | review-architecture | 住宅設計審査(寸法・動線・法規感覚・整合) |
| 素材 | asset-maker | テクスチャ/モデル生成(PIL・Blender) |
| アプリ改修 | app-brushup-worker / app-brushup-reviewer | index.html 側の描画品質改善と、その差分レビュー |

## ラウンド運用

1. **調査**: 調査エージェントがクオリティライン(=合格基準)を具体値で更新する。
   基準は docs/quality-bar.md に追記し、以後の評価はこの基準に照らす。
2. **実装**: plan-implementer が生成スクリプトを変更。コミット単位を小さく保つ。
3. **機械検査**: `python3 tools/lint_plan.py` 違反0が実装完了の必要条件。
4. **評価**: レビューエージェント3種が独立に審査し、指摘を
   「重大(ロールバック要求可) / 要修正 / 提案」で格付けする。
5. **判定**: オーケストレータが指摘を裁定。重大指摘が残るラウンドの変更は
   `git revert` / リセットでロールバックし、原因をルーブリックに追記する。
6. 重大0・要修正0 になるまで 2〜5 を周回する。

## 目視レビューの手順 (全レビュアー共通)

- devサーバ: `python3 tools/dev_server.py <port>` → `index.html` を開く
- 3Dカメラはコンソールから直接指定できる:
  `applyStashedCamera({pos:[x,y,z], target:[x,y,z]})` (単位m, x=plan x/1000,
  z=plan y/1000, y=高さ。1F目線は y≈1.95、2F目線は y≈4.85)
- モード切替(平面図/外観3D/内観3D)・階切替の直後はビュー初期化で
  カメラが上書きされるため、描画完了後にもう一度適用する
- 最低限の定点: 南正面(道路から)・東西北の各面・玄関前・LDK目線2方向・
  各居室目線・階段見上げ/見下ろし・敷地と道路の際・塀の足元

## これまでに検出した不良クラス (再発チェックリスト)

- 向きの規約違反: 階段の上り方向 / 廻り階段の抜け方向 / 外階段・スロープの
  高低 / 家具の正面(キャビネットの背面が通路を向く等)
- 建具: window-door の doorOpenState 未指定(開いた見た目になる) /
  サッシ色の不統一 / 窓上端の通り不揃い / 掘り込み小口の白見え
- 動線: ドア・折戸の開閉域や正面に家具 / 掃き出し窓の前1m / 通路幅不足
  (キッチン通路は1000mm以上) / どこからも入れない部屋(PS以外)
- 接地: 敷地サーフェス(-35mm)上のアイテムの浮き / 道路端の見切れ /
  電柱モデル付属の電線が敷地上空を横切る
- 代用の禁止: custom-block の箱でモデルの代用をしない(床仕上げ・門柱を除く)。
  カタログ(fmp 445点 + im0261 240点)から寸法・高さの合うモデルを選ぶ。
  高さ種別に注意(例: fmp-Table34 は h629 のローテーブルで机ではない)

## ロールバック規約

- ラウンドの変更は1コミットにまとめ、レビューで重大指摘が出たら
  そのコミットを revert して再実装する(部分手直しで濁さない)
- 生成物(assets/default_plan.json)は常に tools/make_default_plan_2f.py から
  再生成できる状態を保つ(JSONへの手パッチ禁止)
