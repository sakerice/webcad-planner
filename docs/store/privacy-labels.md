## 申告の考え方

Apple の申告で「収集する」に当たるのは、データを端末の外へ送り、運営者か、運営者が組み込んだ提携先（広告の会社・AI の事業者など）が、その要求に応えるのに要る時間より長く読める形で持つ場合。広告の SDK が集める分は、運営者の収集として申告する。

このアプリで分かれ目になるのは、図面の画像やチャットの文のように「当方のサーバーは保存しないが、AI の事業者に渡る物」をどう数えるか。下の「決めてもらうこと 1」に選択肢を書いた。

## 申告の案

AdMob の 7 行は、同じ利用者の「かさねて」が 2026-11-20 に App Store Connect へ入れた形（AdMob の SDK 13.11.0 の申告ファイルに合わせた物）を写した。house-planner 自身の分は、下の「決めてもらうこと」で勧める手を入れてある。

| データの種類 | 用途 | ユーザに結びつくか | トラッキングに使うか | どこから |

## 決めてもらうこと

### 1. AI の事業者に渡すだけの物を「収集」と数えるか

問題。図面の画像・補足の文・チャットの文は、当方のサーバーは保存しないが、AI の事業者に渡る。これを申告に入れるかどうか。

原因。Apple の定義は「その要求に応えるのに要る時間より長く、運営者か提携先が読める形で持つ」こと。Anthropic は受け取った内容を不正の監視のために一定の期間（標準 30 日）残すと定めている（2026-11-21 の調査メモが各社の規約から確かめた事実。今回は読み直していない）。OpenAI には `store: false` で送るが、background の処理のために答えが約 10 分置かれる（`worker/openai.mjs` 167〜168 行のコメント）。★AIレンダーで Google に送る絵は、学習には使われないが、キャッシュが最大 24 時間残る（PR #162 の説明）。つまり、提携先が要求の処理より長く持つ物がある。

課題。少なく申告して審査で指摘されるか、多めに申告して利用者に「集めている」と見えるか。

取れる手。

| 手 | 得られること | 手間・残るもの |
|---|---|---|
| 申告する（上の表のとおり「写真またはビデオ」と「その他のユーザコンテンツ」、用途はアプリの機能） | 事業者が残す期間があっても説明が合う。審査の 5.1.2(i)（第三者の AI に渡すなら示して許可を得る）とも筋がそろう | 製品ページに「ユーザコンテンツを収集」と出る。用途がアプリの機能だけなので、トラッキングや広告とは結びつかない見え方になる |
| 申告しない（その場の処理だけとみなす） | 製品ページの項目が AdMob の分だけになる | 事業者が 30 日残すことと食い違う。指摘されれば直して出し直し |

勧める手。申告する。共同編集の間取りは当方が 60 日持つので、どちらにしても「その他のユーザコンテンツ」は申告が要る。図面の画像も同じ行の並びに足すだけで済む。

### 2. ユーザコンテンツを「ユーザに結びつく」とするか

事実。アカウントが無い。ルームの中身には表示名も端末の識別子も残さない（上の表）。回数を数える IP は、中身とは別の所に、中身と結びつけずに置く。AI の事業者へは当方の鍵で送り、利用者の IP や識別子は付けない（`worker/anthropic.mjs` 23 行の送り先へ、Worker から送る）。

取れる手。「いいえ」は事実どおり。「はい」は、かさねてと東京バズマップで「迷うものは、はいに寄せる」とした方針に合う。

勧める手。「いいえ」。東京バズマップが「はい」にしたのは、共有の一覧に表示名と「誰が足したか」を保存しているためで、house-planner のルームにはそれが無い。迷うなら「はい」にしても審査で困ることは無い。

### 3. 当方のサーバーに残る IP アドレスと呼び出しの記録をどう申告するか

事実。IP アドレスは Apple の申告の種類に、それだけの項目が無い。当方は IP を回数を数えるために 2 日分持ち、Cloudflare の呼び出しの記録には IP から分かるおおよその地域が 3〜7 日残る。

取れる手。

| 手 | 内容 | 残るもの |
|---|---|---|
| おおよその場所の行の用途に「アプリの機能」を足す | 記録に地域が残ることと申告が合う | 項目が増えるだけで、種類は増えない |
| 足さない | AdMob の分の行だけ | 記録に地域が残る間は、少なめの申告になる |
| 呼び出しの記録を止める（`wrangler.toml` に `invocation_logs = false`。調査メモの決めること B） | 地域が残らなくなり、足す理由が無くなる | 本番で落ちたときの原因が追いにくくなる |

勧める手。呼び出しの記録を残すなら「アプリの機能」を足す。止めるなら足さない。調査メモの決めること B（止めるか）の答えに合わせる。

### 4. 共同編集の表示名と乱数

つないでいる間だけ使い、保存しない。勧める手は申告しない（東京バズマップは保存するので「ユーザ ID」として申告したが、こちらは保存しない）。★アプリ版で表示名の扱いを変える（保存する）なら申告に足す。

## トラッキングと追跡の許可（ATT）

- ★アプリは追跡の許可（App Tracking Transparency）を尋ねる。断られても、広告は合わせない広告で出し、機能はすべて使える（かさねてと同じ作りの予定。まだ実装は無い）。
- 尋ねる時期は、起動の直後を避け、最初の間取りを開いたあとにする案（調査メモ 3 章 E）。
- Info.plist の説明文 `NSUserTrackingUsageDescription` の案（かさねてと同じ）。「あなたに合った広告を表示するために使います。許可しなくても、アプリはそのまま使えます。」

## プライバシーマニフェスト（PrivacyInfo.xcprivacy）

- ★アプリの殻ができたら、アプリ自身の分を入れる。トラッキングは無し。収集データは上の表の house-planner の分。理由の申告が要る API は、ビルドしたあとに Xcode の Privacy Report で確かめる。かさねては、AdMob と一緒に入る部品が `fstat` を使うため、ファイルの日時（`C617.1`）を足していた（調査メモ `research-ios-app.md` 1-3）。
