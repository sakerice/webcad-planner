# 洋館273モデルの公開範囲

この公開版は、凍結済みの273モデルを変更せず、実行用データ・編集元・再生成に必要なコード・正面／背面の検証資料を残したものです。完全な制作・検証パッケージはLibraryに保存しています。

## 点数と用途

- カタログに載るモデルは273点です。主manifestのID、寸法、素材変更の部位、配置情報、ファイル参照は変更していません。
- 別納の仕上げ素材12種類はLibrary保存のみとし、このPRのモデル数・公開ファイルに含めません。
- 別納の設置検証5シーンは検証用です。追加のカタログIDや新規モデルとして数えず、Library側で保存します。
- 階段、建具、水回りなどは手動配置する静的モデルです。壁・床の自動開口、ホストへの自動追従、ドアの開閉機構、経路探索、衝突・物理動作、構造・消防・法令への適合を実装・保証するものではありません。各モデルのmanifestに記載した範囲・制約が優先します。

## GitHubに残すもの

- 273モデルのGLB、公開用サムネイル・平面画像、主manifest。
- 主manifestから参照する編集可能なBlender原本、必要な別のネイティブ編集元、検証JSON、生成スクリプト、正面・背面画像。現行の左右・底面・設置証拠などの追加参照も残します。
- 生成スクリプトの依存先、共有・ファミリー別の補助コード、再生成や後処理で読む可能性のあるJSON・説明文。
- 保持するコードで使う既存入力GLBと、ファミリー内の実行用モデル・プレビュー参照を解決する同一内容の別パス。

根拠は [納品物の規定](../../../../docs/asset-sets.md#納めるもの) の12–18行、[作業方針](../../../../AGENTS.md) の35–36行です。前者はサイト用モデル・2種の公開画像・manifest・編集元・生成スクリプト・正面／背面画像・権利台帳を要求します。後者は実行環境の検証画像の保存も求めます。Blenderのオフライン画像は、アプリ上の実行確認の代わりにはなりません。

## Library側で保管するもの

主manifestから参照されず、生成に必要ない追加QAレンダー、一覧画像、検証専用シーン、中間書き出し・再書き出し、一部の独立検証ツールをこのPRから外しています。削除した成果物ではなく、完全版パッケージに保管した成果物です。

過去のfinalize・QA再実行スクリプトには、完全版の旧チェックサム一覧、検証シーン、設置画像や当時の作業パスを必要とするものがあります。コードがこのPRに残っていても、独立検証の全工程をGitHubの縮小版だけで再実行できるとは保証しません。必要な場合はLibraryの完全版を併用します。主要な生成処理と、原本からの製品画像生成に必要な依存先は静的に確認しました。今回の公開範囲確認ではモデルの再生成・テストは実行していません。

特に以下は完全版の検証成果物を前提とする履歴用ワークフローです。

- scaled_beds_additions/finalize_delivery.py: 既存18点の完全な旧納品一覧を照合します。
- modular_architecture_completion/finalize_candidate.py: 保存済みの組立シーンとその画像を照合します。
- fitted_door_closure、service_softgoods、window_dressingsのfinalize処理: 設置検証画像からQA一覧を作ります。

## 受け入れ確認

[納品の検査](../../../../docs/asset-sets.md#受け入れの検査) にあるID・寸法・モデル／画像・素材変更の定義などの検査に加え、アプリでセットの表示、平面図と3Dの向き、部位別の色変更を確認する必要があります。公開範囲を整理したことだけを理由に、このアプリ上の確認やモデル品質の受け入れが完了したとは扱いません。

ブランチ／PRへの公開と、本番mainへの反映は別の操作です。本番反映はAGENTS.mdの5–24行の許可手順に従います。
